# 批量修复的范围控制：`abook repair --only`

`repair` 原本只有一个开关：`--apply`。它的含义是"该修的全修"。

这个语义在一次真实事故里暴露成问题：为修 3 条记录的引用前缀，执行
`repair --apply`，它同时给 248 条补了 `SIZE`、给 242 条从 `CONCEPTS` 派生了
`KEYS`——**268 条记录被改，改的是没有版本控制、没有备份的真库**。

那些派生值本身没算错。错的是范围：调用方表达的是"修引用"，工具执行的是
"修所有能修的"，而中间没有任何一步能让调用方说清范围。

## 可用类别

```
abook repair --apply --only refs
abook repair --apply --only size
```

| 类别 | 做什么 |
|---|---|
| `id` | ID 对齐文件名（只在文件名规范、ID 不规范时动） |
| `format` | 补 `FORMAT` |
| `enum` | `KIND`/`MATURITY`/`AUTHORITY`/`STATUS`/`SIZE` 枚举大小写归正 |
| `refs` | 引用值还原为规范身份 |
| `sep` | 列表字段的 ASCII 分号改为逗号 |
| `trim` | 字段值去首尾空白 |
| `size` | 按正文长度补 `SIZE` |
| `keys` | `KEYS` 与 `CONCEPTS` 互为派生 |

不写 `--only` 表示全做，与旧行为一致。

## 实现要点

类别判断必须**连 `set()` 一起跳过**，不能只过滤日志行：写盘是按 `p.fields`
全量落地的，只在日志里不记录的话，字段照样被改，日志却看起来很干净。
这一点有自检盯着——`repair --only refs` 跑完后记录里不能多出任何
`SIZE`/`KEYS`/`FORMAT`。

## 顺带查出的双重登记

加 `--only` 时它被拒，报"无法识别的参数"。原因是参数名要**同时**出现在两处：
全局 `KNOWN_PARAMS`（判断"这个名字是否存在"）和每命令参数表 `spec::SPEC`
（判断"这个命令读不读它"）。两处都要写。

这就是"同一信息存两处，迟早不一致"的教科书例子——参数表本来就是把这个命令
读哪些参数又列了一遍。现在 `known()` 也查参数表，手写清单只作为表里尚未收录
的补充。

同一个根因还牵出另一处：`selftest` 的帮助示例写着 `--only 1`，参数表却没登记，
于是照着示例敲就被拒。**帮助里宣传的参数必须真的能用**，示例文字也是契约的
一部分。

## `--only` 必须真的只跑那一条

`selftest --only 1` 最初只过滤了第一条解析用例，后面一百多个检查块照跑——
参数说"只跑一条"，实际该等的一分钟还是等一分钟。现在它跑完那一条就返回。

要么做到，要么别广告它。
